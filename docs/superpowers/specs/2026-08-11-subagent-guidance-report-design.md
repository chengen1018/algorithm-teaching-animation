# Subagent 指引讀取問題改善報告：文字版簡報設計

## 目標

整理一份繁體中文、可直接用於口頭報告的文字版簡報，清楚說明：過去以 `.codex/agents` custom agent 管理角色時，可能無法穩定讀取正確的 Markdown 指引；目前改由主 Agent 直接建立一般 subagent，並在派遣訊息中明確提供所有必要檔案的絕對路徑，以降低設定複雜度並提高執行可靠性。

## 對象與形式

- 對象：需要了解這次工具流程改善的人員，不假設熟悉 Codex agent 設定細節。
- 形式：純文字、逐頁簡報結構，不建立 PPT/PPTX 檔案。
- 篇幅：六頁左右，不綁定報告時間。
- 語氣：清楚、簡潔、偏技術報告，但避免不必要的設定細節。

## 敘事方式

採用「問題 → 原因 → 解法 → 新流程 → 效益」的問題解決敘事，並在適合處加入改善前後對照。這能同時交代為何要改、具體怎麼改，以及改善帶來的價值。

## 頁面結構

1. **主題與改善目標**：一句話說明這次要解決的是 subagent 無法可靠取得角色指引的問題。
2. **原本做法與遇到的問題**：說明透過 `.codex/agents` 建立 custom agent，以及 Markdown 指引可能沒有被正確讀取。
3. **問題核心**：角色名稱或 custom agent 設定不能保證 subagent 已取得正確、完整、最新版的工作規則。
4. **目前的解決方法**：由主 Agent 直接建立 subagent，派遣時明確指定角色、工作階段、project root、角色規格、必要參考、輸入與輸出的絕對路徑。
5. **新流程與防呆機制**：subagent 先完整讀取指定文件，再執行工作；無法讀取或資料矛盾時回報 `BLOCKED`，完成時回報 `DONE`；主 Agent 再確認必要產物與關卡結果。
6. **改善成果與結論**：減少 `.codex/agents` custom agent 設定、降低找錯或漏讀指引的風險、讓派遣內容可追蹤，並使工具更容易維護與使用。

## 必須維持的技術準確性

- 不宣稱 subagent 會自動找到所有規則；必要文件必須由主 Agent 在派遣訊息中明確指定。
- 所有角色規格、參考文件、project root、必要輸入及預期輸出應使用絕對路徑。
- subagent 必須在開始任何動作前完整閱讀指定角色規格與必要參考。
- 若指定文件無法讀取，主 Agent應提供完整角色規格內容，而不是自行摘要或讓 subagent 猜測。
- subagent 的 `DONE` 只是狀態回報；主 Agent仍需確認產物存在並符合目前關卡要求。

## 成功標準

讀者看完後應能回答三件事：原本出了什麼問題、現在如何派遣 subagent、為什麼新方法更簡單且可靠。
