# 動畫共同設計階段改寫規格

## 目標

重寫 `ANIMATION_DESIGN` 的 `DESIGN_DEVELOPMENT`，使主要 Agent 與使用者逐步共同設計演算法教學動畫。這個階段只處理教學流程、場景內容、解說重點與具體動畫演示方式，不使用 high-impact 分類、風險盤點或複雜的版本治理流程取代動畫設計。

## 角色分工

- 主要 Agent 直接負責需求銜接、逐步共同設計與 `animation_design.md` 更新。
- `animation-design-reviewer` sub-agent 只在完整設計完成後執行獨立內容品質檢查。
- 後續腳本、旁白、Manim 實作與成品 QA 仍可交由各自的 sub-agent。

主要 Agent 必須直接與使用者互動，不得把逐步提問交給 designer sub-agent 再透過主要 Agent 轉送。

## 共同設計方式

主要 Agent 每次只處理一個設計決定。只有當某個教學部分確實存在多種有意義的呈現方式時，才提出三個方案。

每個方案必須是一個完整的教學呈現單位，同時說明：

- 畫面會出現什麼；
- 解說重點；
- 觀眾實際會看到的動畫動作順序；
- 這種方式如何幫助觀眾理解；
- Agent 推薦哪個方案及推薦理由。

使用者可以選擇其中一個方案、混合不同方案、修改方案，或提出自己的具體設計。只要使用者提出明確設計，主要 Agent 就採用並整合。

使用者做出決定後，主要 Agent 直接將結果寫入 `animation_design.md` 並進入下一個設計決定，不在對話中重述決定要求二次確認。

字體大小、方格間距、局部位置、精確秒數與一般淡出時間等實作細節，不屬於共同設計問題，由 Agent 自行處理。

## 固定教學流程

動畫固定包含六個教學部分，且每個部分對應一個獨立的 Manim `Scene`：

1. 問題與目標；
2. 核心觀念；
3. 演算法特有的重要資料與狀態；
4. 示範一次關鍵動作；
5. 完整演示演算法；
6. 最終結果與簡短回顧。

不加入「抽出重複規律」，也不加入要求觀眾預測下一步、回答問題或進行互動的段落。

### 觀眾知識預設

若使用者沒有指定其他程度，預設觀眾已理解基本程式設計與常見資料結構，包括陣列、索引、變數、迴圈與條件判斷。

第三個 Scene 只解釋理解該演算法所必須知道的特殊資料、狀態或觀念，不逐一介紹一般畫面元件或基礎資料結構。

## `animation_design.md` 格式

文件固定以六個 Scene 分章。每個 Scene 都必須記錄：

- 教學目的；
- 解說重點；
- 畫面內容；
- 具體動畫演示順序。

「解說重點」只記錄該段需要解釋的內容與觀眾應理解的重點，不撰寫完整旁白台詞。

「具體動畫演示順序」必須描述觀眾實際會看到的連續動作，例如哪些元素先亮起、如何比較、哪些內容如何淡出或移動、狀態框如何更新，以及下一個狀態如何出現。不得只以「演示比較」或「排除不可能區間」等抽象句子帶過。

## Manim 場景結構

- 六個教學部分必須實作為六個獨立 Manim `Scene` 類別，不使用 `Section` 代替。
- 每個 Scene 擁有獨立畫面與狀態，避免前一幕的物件、文字或版面影響下一幕。
- Scene 之間固定淡出至空白，再淡入下一幕，不將轉場列為使用者設計決定。
- 六個 Scene 個別渲染後，依固定順序合併為一支完整教學影片。

## 獨立內容審查

完整設計完成後，派遣獨立的 `animation-design-reviewer`。Reviewer 只檢查：

- 演算法演示是否正確；
- 範例與最終結果是否正確；
- 六個 Scene 的教學流程是否連貫；
- 畫面、解說重點與動畫動作是否一致；
- 動畫是否清楚呈現原因、動作與結果；
- 視覺表示是否前後一致；
- 文件是否具體到足以供後續腳本與動畫製作；
- 使用者選定的設計是否完整保留。

Reviewer 只報告問題，不直接修改 `animation_design.md`，也不得重新設計動畫或推翻使用者基於喜好做出的選擇。

移除 SHA-256、證據矩陣、Full Review、Delta Review、high-impact 缺口分類及相關版本治理要求。

## 修正與完成流程

1. 主要 Agent 與使用者逐步完成六個 Scene 的設計。
2. Reviewer 執行內容品質檢查。
3. 若修正不改變使用者選定的教學呈現方式，主要 Agent 直接修正。
4. 若修正會改變使用者選定的教學呈現方式，主要 Agent 必須重新提出修正方案並詢問使用者，不得自行修改。
5. 修正後再次交給 reviewer 檢查，直到沒有品質問題。
6. 使用者最後檢查完整的 `animation_design.md`。
7. 只有使用者明確核准後，才能進入下一階段。

## 不屬於此階段

- 完整旁白台詞；
- Manim 程式碼；
- 精確秒數與底層動畫 API；
- 字體、間距及其他一般排版微調；
- high-impact／low-impact 分類與 inventory；
- 方案風險治理、SHA-256 綁定及證據矩陣。

## 驗收條件

- 主要 Agent 而非 designer sub-agent 負責面向使用者的共同設計。
- 只有存在多種有意義的教學呈現方式時才提出三個完整方案。
- `animation_design.md` 含六個獨立 Scene，且每個 Scene 都有四項必要內容。
- 動畫演示順序具體到能讓使用者理解實際畫面如何演出。
- Reviewer 僅執行內容品質檢查，不執行版本治理或設計決策。
- Reviewer 修正循環通過後，取得使用者對完整設計的最終核准。
