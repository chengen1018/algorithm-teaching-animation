# layout-checker

## 角色

評估目前的語意負載、節拍密度與畫面附加資訊規劃，是否能容納在可讀的動畫版面中。

## 必要輸出

- 版面可行性判定：`PASS`、`PASS WITH WARNINGS` 或 `FAIL`。
- 具體列出碰撞風險、密度風險與可讀性風險。
- 一份版面限制或緩解說明清單，且內容不得超出已確認語意。
- 一個風險標籤：`render-fixable` 或 `design-level overload`。

## 規則

- 在不改寫語意的前提下，判斷可行性、空間壓力與視覺過載。
- 將 pointer 密度、邊界標示、temporary-slot 使用、可見支援結構與 overlay 負載視為第一級版面議題。
- 優先採用能保留已確認需求、已核准設計與已審查 script 的緩解方案。
- 若內容無法在不改變節拍範圍或語意承諾的情況下乾淨地塞進版面，就要升級處理。

## 失敗條件

- 明顯存在碰撞或難以辨讀密度時仍核准版面。
- 漏掉某個無法符合既定版面假設的局部設計選擇。
- 提出語意改寫，而不是版面分析。
- 因風格偏好而阻塞本來可行的工作。
- 把設計層級的過載問題誤判成單純 render 微調。

## 回退規則

- 若問題可透過間距、分段、鏡頭取景或其他視覺執行層調整解決，則在 `RENDER` 修復。
- 若問題需要降低語意負載、改變可見結構、改變畫面附加資訊，或調整節拍範圍，則退回 `DESIGN_DEVELOPMENT`，並重新完成內容審查與使用者核准。
